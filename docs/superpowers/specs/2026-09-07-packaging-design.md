# Packaging and Distribution — Design

Date: 2026-09-07
Phase: 4 (see [ROADMAP](../../ROADMAP.md))
Status: Approved design, pending implementation plan

## 1. Purpose

Turn the app into something a friend can install: a frozen `Nebula.app` inside a
`.dmg`, with instructions for the two things macOS will otherwise fail at
silently.

Covers the PRD's **Distribution** checklist, and closes the single-instance
guard (PRD §15) — the last unchecked **Time Tracking** item.

## 2. What the spike already settled

The packaging spike (`spikes/2026-09-01-packaging-spike-findings.md`) built a
working 28MB bundle and threw it away. This phase is therefore known work rather
than exploration:

- `PROJECT_ROOT` needs `sys._MEIPASS` handling; nothing else does.
- `--add-data` resolves relative to `--specpath`, not the working directory.
- PyInstaller's contrib hooks already collect pywebview's runtime-globbed JS.
- `PyObjCTest` is already absent; no exclusion needed.
- `spctl -a` reports `rejected`, confirming the PRD §26 Gatekeeper block, and
  `xattr -cr` clears the quarantine flag.
- Launching through `open Nebula.app` behaves identically to running the inner
  binary; the bundle serves the real built frontend.

## 3. Single instance comes free

PRD §15 requires that a second launch focus the existing window rather than
start a second process. **This needs no code.**

Measured during this design: with `CFBundleIdentifier` left as PyInstaller's
default — the bare name — `open` three times produced three running processes.
With a reverse-DNS identifier, `com.giovanniiskandar.nebula`, the second `open`
left exactly one. LaunchServices single-instances an app keyed on that
identifier.

So the identifier the spike flagged for a different reason (collisions, and
what macOS keys preferences off) also closes §15.

Two measured caveats, neither affecting the shipped app:

- `open -n` still forces a second instance. That is a deliberate act, not an
  accident.
- Running from source (`uv run nebula`) has no protection at all. The shipped
  artifact is the `.app`; adding a lock file for the development path would be
  code with no user.

Not directly confirmed: that the existing window comes *forward* rather than
merely not launching twice. `open` activates a running app, but the check needs
accessibility permission this machine does not grant. It stays a manual check.

## 4. Output goes in `release/`, not `dist/`

PyInstaller defaults its output to `dist/`, which is **already Vite's build
output**. Colliding them would have each build overwriting the other, and
`pnpm build` uses `emptyOutDir`.

The app and disk image go to `release/`, added to `.gitignore` alongside `dist/`.
The staging directory the disk image is built from lives inside `release/` too,
so one ignore rule covers everything the build produces.

## 5. The one source change

```python
if hasattr(sys, "_MEIPASS"):        # running from a PyInstaller bundle
    PROJECT_ROOT = Path(sys._MEIPASS)
else:
    PROJECT_ROOT = Path(__file__).resolve().parents[2]
```

`DIST_INDEX` and `ICON_PATH` derive from it. `store.data_path` already uses
`Path.home()` and needs nothing — a bundled app's working directory is `/`, so
that absoluteness was deliberate from 3a.

## 6. The build

A committed `nebula.spec` at the repository root — PyInstaller's own format, and
where the `Info.plist` values live:

| Key | Value |
|---|---|
| `CFBundleIdentifier` | `com.giovanniiskandar.nebula` (see §3) |
| `CFBundleShortVersionString` | read from `pyproject.toml` at build time |
| `CFBundleName`, `CFBundleDisplayName` | `Nebula` |
| `CFBundleIconFile` | `Nebula.icns` |

Reading the version from `pyproject.toml` rather than repeating it is what stops
the spike's observed drift, where the plist said `0.0.0` and the project said
`0.1.0`.

`scripts/build.sh` orchestrates: `nvm use` → `pnpm build` → `pyinstaller
nebula.spec` → `hdiutil`. PyInstaller becomes a dev dependency rather than the
spike's throwaway `--with pyinstaller`.

The frontend build is not optional and not assumed: the script runs it, because
a stale or missing `dist/` produces a bundle that fails at runtime rather than
at build time.

## 7. The disk image

`hdiutil create` from a staging directory holding `Nebula.app`, a symlink to
`/Applications`, and the instructions file. Dragging across is then
self-explanatory without anyone reading anything.

Named `Nebula-<version>.dmg`, with the version from the same source as the
plist.

## 8. First-run instructions

A plain `.txt` in the disk image, generated by the build from a source file
committed at `packaging/first-run.txt` so it is reviewable in the repo. Plain
text because it is more likely to be opened than markdown, and readable without
any app. It covers the two things that fail *silently*:

**Gatekeeper** (PRD §26). The app is unsigned, so macOS refuses it on first
launch. Right-click → Open, or System Settings → Privacy & Security → Open
Anyway. `xattr -cr` is given as the one-line alternative.

**Notifications.** Banners go out through `osascript` and are attributed to
Script Editor, so their visibility is governed by Script Editor's alert style in
System Settings. On the development machine they arrive but do not flash as
banners. A recipient with them switched off gets nothing, and neither the app
nor `osascript`'s exit code can detect it.

## 9. Testing

`tests/test_bundle.py`, marked `slow` and excluded from the pre-commit hook
alongside `gui`, since a full build takes around a minute. The hook's selector
becomes `-m "not gui and not slow"`.

It builds the bundle and then asserts, against the real artifact:

- The window appears — owner `Nebula`, 384 × 684, on layer 25 (always-on-top).
- The frontend actually loads, rather than the card being blank.
- `Info.plist` carries the reverse-DNS identifier and the version from
  `pyproject.toml`.
- A second `open` does not add a process.

That last one turns a one-off measurement into a permanent check. Every
packaging bug found so far appeared only in a real bundle, which is why this
tests the artifact rather than the recipe.

## 10. Out of scope

Developer ID signing and notarisation (PRD §24) — the Gatekeeper override is the
accepted V1 tradeoff. Universal2: arm64 only, since no recipient has an Intel
Mac, and going universal means building against a universal2 Python rather than
uv's. Auto-update, a menu-bar item, and anything else in the §24 backlog.

## 11. The gap this phase cannot close

**The bundle has never run on another Mac**, and nothing here can change that.
Every check runs on the machine that built it, where the interpreter, the fonts
and the frameworks are all already present. The first genuine test of this phase
is a friend double-clicking it.

## 12. Definition of done

1. `scripts/build.sh` produces `release/Nebula.app` and `release/Nebula-0.1.0.dmg`.
2. The app launches from Finder and renders the dashboard against real data.
3. `Info.plist` carries `com.giovanniiskandar.nebula` and `0.1.0`.
4. A second `open` leaves one process running.
5. The disk image mounts showing the app, an `/Applications` symlink, and the
   instructions.
6. `tests/test_bundle.py` passes.
7. Both existing suites still pass, and the hook still skips the slow test.
